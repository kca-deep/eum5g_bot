## 사용자 질문 → 답변까지의 흐름

사용자가 "5G 특화망 유형별 차이점을 알려주세요"라고 질문했을 때, 내부에서 일어나는 일을 **단계별**로 설명합니다.

### Step 1. 사용자가 질문을 입력합니다

- 화면 하단 입력창(`ChatInput`)에 텍스트를 입력하고 전송 버튼을 누릅니다.
- 질문이 화면 오른쪽에 말풍선으로 즉시 표시됩니다.
- 화면에 **"관련 자료를 검색 중"** 애니메이션이 나타납니다.

### Step 2. 서버가 관련 문서를 검색합니다 (RAG - 검색 단계)

- 브라우저가 서버의 `/api/chat` 주소로 질문을 전송합니다.
- 서버는 **Dify 지식베이스**에 질문을 보내 관련 문서 조각(chunk)을 검색합니다.
- Dify는 사전에 업로드된 **5G 특화망 가이드라인 PDF**를 벡터(숫자) 형태로 저장해두고 있으며, 질문과 **의미적으로 가장 유사한** 문서 조각 8개를 찾아 돌려줍니다.
- 각 조각에는 **유사도 점수**(0~100%)와 **원본 페이지 번호**가 포함됩니다.

### Step 3. 시스템 프롬프트를 조립합니다

- 서버는 검색된 문서 조각들을 **시스템 프롬프트 템플릿**(`src/prompts/system.md`)에 삽입합니다.
- 이 템플릿에는 AI의 역할, 답변 형식 규칙(표 사용, 출처 표기 등), 답변 지침이 정의되어 있습니다.
- 조립된 프롬프트는 **"이 문서들을 참고해서, 이 규칙에 맞게, 사용자 질문에 답변해라"** 라는 지시서 역할을 합니다.

### Step 4. OpenAI에 답변을 요청합니다 (RAG - 생성 단계)

- 화면에 **"답변을 생성 중"** 애니메이션으로 전환됩니다.
- 서버는 조립된 프롬프트 + 사용자 질문을 **OpenAI GPT 모델**에 전달합니다.
- GPT는 검색된 가이드라인 내용을 근거로 답변을 **토큰(단어 조각) 단위로 실시간 생성**합니다.

### Step 5. 실시간으로 답변이 화면에 표시됩니다

- 서버는 GPT가 생성하는 답변을 **SSE(Server-Sent Events)** 방식으로 브라우저에 실시간 전달합니다.
- 브라우저는 받은 텍스트를 즉시 화면에 추가하여, 글자가 하나씩 타이핑되는 것처럼 보여줍니다.
- 답변에 포함된 마크다운(표, 굵은 글씨, 목록 등)은 자동으로 서식이 적용됩니다.

### Step 6. 출처 정보가 표시됩니다

- 답변 스트리밍이 끝나면, 서버는 참조한 문서 목록(출처)을 함께 전송합니다.
- 답변 하단에 **원본 가이드라인의 페이지 번호**가 표시되어 사용자가 원문을 확인할 수 있습니다.
- 답변 옆에 **복사 버튼**이 나타나 클립보드에 복사할 수 있습니다.

## 핵심 기술 파이프라인 (RAG)

이 서비스는 **RAG(Retrieval-Augmented Generation, 검색 증강 생성)** 방식을 사용합니다.
쉽게 말해, **AI가 답변하기 전에 먼저 관련 자료를 찾아보고, 그 자료를 근거로 답변하는 방식**입니다.

```
RAG 파이프라인 요약

┌──────────────┐     ┌──────────────────┐     ┌──────────────────┐
│  사용자 질문   │ ──→ │  ① 문서 검색       │ ──→ │  ② 답변 생성       │
│              │     │  (Dify)           │     │  (OpenAI GPT)     │
│ "5G 특화망   │     │                   │     │                   │
│  유형 차이?" │     │  가이드라인에서    │     │  검색된 문서를     │
│              │     │  관련 내용 8개     │     │  참고하여 답변     │
│              │     │  조각을 찾아옴     │     │  생성              │
└──────────────┘     └──────────────────┘     └──────────────────┘
```

### RAG를 사용하는 이유

| 방식 | 장점 | 단점 |
|------|------|------|
| **AI 단독 답변** | 빠름 | 최신 정보 모름, 출처 없음, 환각(거짓 답변) 위험 |
| **RAG 방식** (이 서비스) | 공식 문서 기반, 출처 명시, 정확도 높음 | 검색 단계 추가로 약간 느림 |

### 사전 준비 과정 (1회성)

RAG가 작동하려면, 가이드라인 문서가 미리 Dify에 등록되어 있어야 합니다.

```
5G 특화망 가이드라인 PDF
         │
         ▼
   텍스트 추출 & 분할
   (문서를 작은 조각으로 나눔)
         │
         ▼
   벡터 임베딩 변환
   (텍스트를 숫자 배열로 변환)
         │
         ▼
   Dify 지식베이스에 저장
   (검색 가능한 상태)
```

## 주요 파일 설명

### `/api/chat` — 서버 핵심 로직 (`src/app/api/chat/route.ts`)

사용자 질문을 받아 답변을 생성하는 **서버 API**입니다. 아래 3단계를 순서대로 수행합니다.

| 단계 | 함수명 | 하는 일 |
|------|--------|---------|
| 1단계 | `retrieveChunks()` | Dify 지식베이스에서 질문과 유사한 문서 조각 8개 검색 |
| 2단계 | `buildSystemPrompt()` | 검색 결과 + 답변 규칙 템플릿을 합쳐 시스템 프롬프트 조립 |
| 3단계 | `POST handler` | OpenAI GPT에 프롬프트 전달 → 답변을 SSE 스트리밍으로 전송 |

### `ChatContainer.tsx` — 채팅 흐름 관리

브라우저에서 실행되는 채팅의 **두뇌** 역할입니다.

- 메시지 목록 상태 관리 (질문/답변 저장)
- 서버 응답을 실시간으로 파싱하여 화면에 표시
- 스트리밍 실패 시 일반 요청으로 자동 전환 (폴백)
- 이전 요청 취소 기능 (새 질문 시 이전 스트리밍 중단)

### `system.md` — AI 답변 규칙

AI가 답변할 때 따라야 하는 규칙을 정의한 문서입니다.

- AI의 역할: KCA 이음5G사업팀 공식 어시스턴트
- 답변 형식: 표 우선 사용, 마크다운 서식 규칙
- 출처 표기: 원본 가이드라인 페이지 번호 안내
- 범위 제한: 5G/통신/전파 관련 질문만 답변

## 배포 환경

### Vercel 서버리스 배포

```
코드 Push (GitHub) ──→ Vercel 자동 빌드 ──→ 서비스 배포 (서버리스)
```

| 설정 | 값 | 설명 |
|------|----|------|
| `output` | `standalone` | 독립 실행 가능한 빌드 생성 |
| `vercel.json` | `includeFiles: "src/prompts/**"` | 서버리스 함수에 프롬프트 파일 포함 |
| `vercel.json` | `crons: /api/cron/keepalive` 매일 00:00 UTC | Dify Cloud는 검색·수정이 없는 지식베이스를 무료 7일·유료 30일 뒤 자동 비활성화(검색 인덱스 삭제)하므로 하루 1회 검색해 사용 기록을 남김. 0건이면 `[Keepalive] 실패` 오류 로그 |

> **"서버리스"란?**
> 별도의 서버 컴퓨터를 직접 운영하지 않고, 요청이 들어올 때만 클라우드에서 코드가 실행되는 방식입니다. 요청이 없으면 비용이 발생하지 않습니다.

## 로컬 개발 환경 설정

### 사전 요구사항

- **Node.js** 18 이상
- **npm** (Node.js 설치 시 함께 설치됨)

### 설치 및 실행

```bash
# 1. 의존성 설치
npm install

# 2. 환경 변수 파일 생성
cp .env.local.example .env.local
# .env.local 파일을 열어 실제 API 키를 입력합니다

# 3. 개발 서버 실행
npm run dev
```

브라우저에서 `http://localhost:3000` 으로 접속하면 채팅 화면을 확인할 수 있습니다.

### 빌드 및 프로덕션 실행

```bash
# 프로덕션 빌드
npm run build

# 프로덕션 서버 실행
npm run start
```

---

## 환경 변수 설명

`.env.local.example` 파일을 복사하여 `.env.local`을 만든 뒤, 아래 값을 입력합니다.

| 변수명 | 필수 | 설명 |
|--------|------|------|
| `DIFY_BASE_URL` | O | Dify API 기본 주소 (기본값: `https://api.dify.ai/v1`) |
| `DIFY_DATASET_API_KEY` | O | Dify 지식베이스 전용 API 키 (Dify 콘솔 > 지식베이스 > API Key) |
| `DIFY_DATASET_ID` | O | Dify 지식베이스의 고유 ID |
| `OPENAI_API_KEY` | O | OpenAI API 키 |
| `OPENAI_MODEL` | - | 사용할 GPT 모델명 (기본값: `gpt-4o`) |
| `SUPABASE_URL` | O | 처리 기록 DB 주소 (비우면 기록 없이 답변만 동작) |
| `SUPABASE_SERVICE_ROLE_KEY` | O | 처리 기록 DB 서버 전용 키: Secret key(`sb_secret_…`) 권장, 구형 service_role(JWT)도 가능 (`NEXT_PUBLIC_` 접두어 금지) |
| `OPENAI_REASONING_EFFORT` | - | 추론형 모델(o·gpt-5 이후) 추론 강도 (none·minimal·low·medium·high·xhigh, 비우면 medium, 운영 medium) |
| `CRON_SECRET` | O | 매일 상태 유지 호출 인증값 (Vercel Cron이 자동 전송, 운영 Production에만 등록) |
| `NEXT_PUBLIC_SUPPORT_PHONE` | - | 대화 종료 카드의 지원센터 대표번호 (비우면 지원포털 링크만 표시) |
